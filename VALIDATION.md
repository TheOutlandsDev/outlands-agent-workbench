# Version 0.28 validation

The first complete native qualification passed **1,178 unit methods across 54
suites**, all earlier acceptance stages and the new lifecycle acceptance stage.
That is 1,145 inherited methods plus 19 harness and 14 integration methods. All
**124 qualified code, static and example hashes** stayed unchanged through native
and browser checks. The **624 inherited isolated frontend checks** also passed
(255 inherited and 369 history checks). These are local results, not GitHub CI.

## Scope and evidence classes

Four source modules add a separate QA lifecycle harness, native acceptance and two
regression suites. The existing runner adds those suites and calls the new stage
last. The production engine, Manager, admission, provider paths, review writer,
export gates, Java client, original success harness/worker and all earlier QA/tests
remain byte-identical. Browser JavaScript/CSS are unchanged; HTML changes only the
version badge. No external dependency or service is installed.

The new harness creates two fresh once-only outer roots containing private control,
receipts and an inner unchanged offline workflow. It lets the original launch
validator check the exact configured command, arguments, environment and log
identity before a scoped callback redirects only that command to the fixed
source-bound controlled worker. The callback repeats its finite argument/context
and log checks. It supports no arbitrary command, model or goal.

These are actual controlled local process experiments. They do not run the coding
agent, a model or configured checks, and they create no agent run directory,
result, event, patch or human review. Focused unit/integration tests use explicitly
labelled fake children, source fingerprints and fabricated receipt chains. Those
synthetic tests are separate from actual native process evidence.

the failure case records neither. Armed checkpoint, actual/logical command,
source/control, fixture, PID, stop and exit receipts must agree. Deadline expiry,
missing guard/exit receipts, unexpected artifacts, unsafe storage or containment
cannot qualify as the expected owned Stop. Missing counters remain unknown.

Normal restricted HTTP history/view are real. Explicit metadata search/open,

Read-only restart uses the same source and fixture with fresh managers, tokens and

claims, process/runtime records and receipts remain identical. Every settled

## Retained focused attempts and permissions

The first engine focus passed 19 methods. A second retained 19-method run added
negative environment, new-session and foreign log-file subcases to the existing
argument test; it passed without a harness/API change. Normal owned Git checkout
source directories/files with 0755/0644 are supported, while generated case,
control and receipt storage remains strictly owner-private 0700/0600. Bounded
source traversal rejects unsafe links, writable permissions and excess entries,
depth or bytes. Optional missing reads preserve unknown evidence while unsafe
parents/files still refuse.

The first integration focus ran 14 methods: five passed, and nine methods produced
ten source-permission errors because one used both scenarios as subtests. Two
intermediate directories in the new staging copy had inherited mode 0775. Root
tightened exactly those directories to 0700. The second focus reached the selected
file guard and found two newly generated source files with mode 0664. Their owner
tightened exactly those files to 0644. Source bytes and validation guards stayed
unchanged across these setup corrections. The third focus passed all 14 methods.
Both earlier logs and exact permission receipts remain retained privately. No
native controlled worker, model or check attempt was consumed by either refusal.

A private observer's first static collector incorrectly expected an imported
callable alias to be locally defined. The failed check was retained; correcting
the checker required no observer or application change. Its final 13 static checks
passed. All 624 inherited isolated frontend checks passed on their first run.
The complete native runner then passed on its first attempt under umask 022.

## Browser observations

Four owned native read-only sessions use the actual completed current-source
failure and stop roots, once before and once after restart per case. The private
observer delegates the public CLI and unchanged normal history/view handler;
no feed or Manager method is substituted. It binds the complete native report,
current source/control, typed lifecycle reports and golden native response hashes
before inspection. It guards new execution and mutating HTTP actions and records
finite request paths/statuses outside the fixtures.

Both normal feeds show one Failed run. Diagnostics preserve the existing generic
Request failed label, state that model inference was not used and show zero model
turns. Task remains read-only for the scripted profile; project/model values stay
unchanged. Stop, Accept, Reject and Download remain disabled for the completed
missing-result case. The shared UI still displays Run; the once-only QA claim
refuses another attempt. No Run, Stop, Accept, Reject or download is requested in
this browser phase.

Explicit search, saved review and history list show Unknown decision, unavailable
artifact hashes and an empty incomplete receipt catalog. Inspect stays disabled;
no fabricated selection or detail success is required. Restart clears cached
cards and explicit reads return identical diagnostics, decision, history and form
state. Successful normal history/view and saved review/list response hashes match
the earlier native observations exactly. The browser does not observe the native
RUNNING transition or send the native controlled Stop.

Across four sessions, normal history and run view each receive 24 requests;
search, saved review and receipt list each receive four. Detail, start, Stop,
review-write and export requests remain zero. Four denied GET /favicon.ico
requests return 403 SESSION_REQUIRED; only those recorded paths/responses are
asserted. All browser console warning/error captures and execution guard counters
are zero. No inference or checks occur in the observers.

Each public CLI session adds only its exact outer session/shutdown receipt pair:
eight new files total across four sessions. All preexisting outer/inner fixture
bytes and modes, typed reports and qualified inputs remain unchanged. All four
owned servers exit successfully; direct native ECONNREFUSED probes confirm both
fixed loopback listeners closed.

## Limits, privacy and licensing

This qualifies controlled process failure/owned stop and retained normal/saved
review behavior. It does not qualify an agent's failed checks, a real model,
a Java agent, remote inference cancellation, browser observation of execution,
arbitrary tasks, recovery, source adoption or deployment. Python-level guards are
not operating-system-wide packet auditing. A typed receipt chain assumes trusted
stable single-owner storage; sequential inspections are not atomic multiwriter
snapshots, authenticity attestations or crash-durability guarantees.

Real records, notes, histories, configuration, run roots, worker evidence, patches,
exports, logs, screenshots and private helpers remain outside public source.
The original uncertain Java trial stays held/unqualified; its cause and provider
completion remain unknown. Root compares only its two authorized preservation
hashes, without held Manager/runtime/provider/recovery/retry access. Existing
notices and rights limits remain; licensing stays **UNASSIGNED**. Naming-only
provenance checks do not establish originality, ownership or redistribution rights.
