## Saved-record comparison evidence

Both comparison endpoints read only the private saved store. The controller
accepts two distinct existing 16-hex run IDs and does not call normal history,
worker reconciliation, admission, request-hold association, process ownership,
check execution, model preflight or model request paths. A saved `RUNNING` state
remains as recorded instead of being reconciled into a new state. Original live
selected or unselected project source is not read by comparison.

Tests compare record-tree hashes and hold bytes before and after those reads.
Guards fail if live-state, process, check or provider paths are reached. Unknown
IDs, invalid/same IDs, malformed records, missing sections and bounded-read
failures are refused or represented as Unknown with fixed notes. The selected
display DTOs exclude raw exception fields, metadata source-root and process
fields, check output, prompts and provider-response records. Saved patch text
and goals are intentionally shown in bounded form and remain private project
evidence.

Comparability requires agreeing task evidence for project, goal, selected file
paths, baseline hashes, editable scope, check specifications and budgets, without
fingerprint mismatch or incomplete loader evidence. Unlike inputs generate
explicit difference flags. Exact raw saved-task fingerprints are compared with
the recorded start fingerprint. Missing legacy start fingerprints remain
`NOT_RECORDED`; a start-time match is not reconstructed from later saved bytes.
Patch fingerprint mismatches also remain visible rather than being repaired.

Measurements count recorded request starts and retain only evidenced serialized
request-body byte totals and sums of recorded request times. Legacy or incomplete
measurements remain Unknown. Event corruption/limits, missing finishes, gaps or
invalid records prevent complete byte/time totals and their deltas. An explicitly
evidenced before-send refusal can record zero attempts; absent history does not
become zero. Deltas are right minus left and carry no token/currency accounting,
task wall-time, provider-completion or model-ranking claim.

The browser comparison uses separate saved-record endpoints and pauses normal
polling while opening or open. Its wait for an existing poll is cancellable and
bounded at ten seconds. Selection changes invalidate the old comparison; late
responses are ignored. Closing resumes the existing live view and its normal
polling/reconciliation. This pause does not stop or resolve a provider request.

## Record and display bounds

The saved-run inventory reads at most 200 matching metadata entries and returns
the latest 100 within that inspected set. Directory enumeration stops after
1,024 entries. A partial flag reports omitted inventory; no global newest-100
guarantee is inferred. Selector labels clip at 160 UTF-8 bytes with an explicit
note, while comparison retains the full bounded saved goal.

Metadata, task and result sections each have a 32,768-byte read ceiling. At most
256 event files are considered, with 262,144 bytes per event and a 2 MiB aggregate
read budget. Oversized or invalid sections become unavailable, and partial
measurements are not reconstructed. Each saved patch has a 65,536-byte read
limit, an 8,192 UTF-8 byte display limit, and explicit clipping. The literal
patch-text difference is limited to 16,384 UTF-8 bytes and 240 lines. Unicode
boundaries are preserved. The serialized output is capped at 131,072 bytes.

The file/hash union is bounded to 64 paths; baseline/final check displays to four
rows per side and stage; request diagnostics reduce at most 16 requests. The
comparison contains no apply/export, inference, retry or recovery action. Patch
text differences do not validate either patch against current source.

Directory and record reads are anchored at the private data root. Every path
component below it is opened without following symlinks; file type and hardlink
checks remain enforced. Ancestor-link regressions cover substituted `jobs`,
`tasks` and `runs` directories. The private data root and its own ancestors must
still be trusted and stable. Sequential saved-file reads are not an atomic
snapshot, a multiwriter transaction or universal consistency under concurrent
changes.

## Retained safeguards and historical limits

The full acceptance retains selected-file search/read bounds, stale edit hashes,
protected tests, independent final checks, request-size refusals and reviewed
refresh behavior. Refresh scope, edit permissions, checks, budgets and Java JDK
configuration remain fixed. Old task definitions and run pins remain preserved;
refreshing does not revalidate an old review/export. Interrupted refresh files
remain retained, and only revision links committed by the current config pointer
appear in history. There is no rollback, request replay or hold-clearing path.

The original real uncertain Java run and its hold/result bytes remain unchanged.
Its cause and provider completion remain unknown. No replay, recovery, model
eviction or new real-model qualification occurred. Prior refresh/browser/model
observations and earlier limits remain in
[version 0.6 validation](https://github.com/TheOutlandsDev/outlands-agent-workbench/blob/240d6886c96856483645ed745d91624608112007/VALIDATION.md).

Offline acceptance used Linux. Java remains a compatible launch client for the
Python engine, with a fixed Java compile/main check profile. Maven/Gradle/JUnit
dependency resolution, annotation processors, arbitrary shell commands, package
installation, remote hosting, automatic recovery and unattended queues are not
implemented. Passing a selected check is evidence for that check, not universal
correctness or resistance to adversarial code.

The Git workspace remains an independent selected-file repository. It does not
import the original project's history, remotes, hooks or attributes. A verified
receipt records creation-time checks; later edits require fresh checks and
review. Candidate changes remain uncommitted; the app does not merge or push.
Failed/interrupted operations retain files/logs and block new work for inspection.

The namespace boundary shares the kernel and read-only system/JDK files and has
no cgroup CPU/process-count quotas. Python checks use a 1 GiB address-space limit;
Java checks use 2 GiB address space and a 128 MiB heap per compiler/runtime JVM.
Each check has a ten-second wall-clock timeout and bounded output. Config/source
parents must be trusted and stable; this is not a hardened multiuser service.
A loopback model endpoint alone does not attest where inference executes.

Acceptance used Python 3.12.7, isolated system Python 3.10.12, Git 2.34.1 and
Temurin JDK 21.0.13+9 targeting Java 17. No GitHub CI run is claimed for these local
checks. Licensing remains **UNASSIGNED**; see [origins and licensing](ORIGINS.md).
