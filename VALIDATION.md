## Evidence classes and preserved development outcomes

Unit fixtures use invented selected Python/Java/mixed source and saved check
observations. The engine's loose Git objects and version-2 indexes are generated
in Python; those fixtures execute no Git command or project check. Controller
fixtures create real private Git worktrees but stub checks where documented.
They are separate from the full runner's actual Bubblewrap Python/Java checks
and from the browser's four-test Python and one-main Java recheck results.

The first focused integration run reported one failure and three errors in
adapted synthetic fixtures: wrong history method, strict display/extra fields
and a timestamp older than creation. Those logs remain retained; corrected
fixtures passed. An initial default-sandbox actual trial could not create a
Bubblewrap network namespace and retained its failed job. A fresh host-permitted
trial exposed a normal final-write polling race. The first correction still
allowed a stale marker observation; independent review identified the ordering
gap and deterministic tests cover both creation and recheck transitions.

One new creation-race test then attempted real fixture Git setup while its own
parent command stub was active. The focused error and interrupted full run are
preserved; fixture setup moved outside that stub. Final 31-method integration
and the final full qualification passed. Earlier successful runs also remain
separate. No failed job or unknown outcome was retried, erased or relabelled.
Fresh qualification roots do not resolve earlier evidence.

The browser observed matching copied snapshot/check hashes, one changed editable
file, unchanged protected files, Java requirement facts, independent history,
successful explicit checks, input invalidation and an invented unrelated hold
that left inspection available but Run/Stop disabled. Two automation locators
timed out; successful completion was inspected without repeating the action.
The browser exercised final polling ordering. The later error-only filesystem
normalization was covered offline and changes no normal browser behavior.

## Format, bounds and limits

The new `outlands-snapshot-workspace-recheck-v1` attempt type has its own private
store and never fabricates legacy bundle/model metadata or converts records.
Creation receipts stay historical. A new VERIFIED attempt records configured
checks for those selected bytes at that time, not current freshness after edits.
No snapshot re-export, source adoption, automatic retry, recovery, hold clearing
or model request is provided for this new type.

Current baseline Git semantics and control/index bytes are validated by the
existing direct readers. Version 0.15 saved no historical raw control/index
hashes; current pins are new observations. Unsupported Git state, staged changes,
commits, changed pointers, links, executable selected files and extra files are
refused. The original selected baseline must still be available and pinned.

| Input/output | Bound |
| --- | --- |
| Selected snapshot | 32 UTF-8 files, 32,768 bytes/file, 131,072 aggregate |
| Creation archive / full checks | 2 MiB each |
| Config/task/receipt | 262,144 bytes each |
| Controller action | 32,768 bytes |
| Inspection / preview | 65,536 / 131,072 bytes |
| Display output | 4,096 characters/check, explicit clipping |
| Attempt history | 200 attempts, 2 MiB aggregate raw receipts |
| New receipt reserve / history JSON | 262,144 bytes each |
| Preview | One memory draft, five minutes, one explicit use |

The host/private store and configured projects must remain trusted and stable.
Sequential guards are not atomic multiwriter snapshots or proof of no transient
mutation. Passing checks and unsigned hashes do not prove authenticity, source
correctness, provider completion, model competence or adoption permission. No
deployment, service change or commit of candidate edits is performed.
